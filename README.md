# FlowPilot — AI業務フロー自動化システム

Googleフォームに届いた問い合わせを AI（OpenAI API）が分析し、
**案件管理（スプレッドシート）→ 対応タスク（Google Tasks）→ 返信メールの下書き（Gmail）** までを自動で準備するシステムです。

- メールは **下書きを作るだけ** で、自動送信は一切しません（最後は必ず人が確認して送信）。
- すべて **架空の企業・顧客データ** で動作します（デモ企業：株式会社みなと設備工業（架空））。
- 会社名・分類・返信トーンなどは「設定」シートで変更でき、他の業種にも使えます。

## 処理の流れ

```
お客様がフォーム送信
   │
   ▼
① 受付：受付ID（FP-20261112-0001 形式）を発行し、原文をすぐ「案件管理」に保存 … AI処理状況=受付済
   │
   ▼
② AI分析：分類・要約・優先度・必要な対応・期限・不足情報・返信文案を JSON で生成
   │        → プログラムで検証（原文に無い期限・金額・日付、命令文の混入をチェック）
   ▼
③ Google Tasks にタスク作成（期限が明記されている場合のみ期限を設定）
   │
   ▼
④ Gmail に返信の下書きを作成（送信はしない）
   │
   ▼
⑤ AI処理状況 = 完了／要確認／エラー → 担当者が確認して対応
```

## コマンド（Claude Code / PowerShell から実行）


## スプレッドシートの構成

| シート | 内容 |
|---|---|
| 案件管理 | 1行＝1件の問い合わせ。「対応状況」はプルダウンで担当者が変更 |
| ダッシュボード | 未対応・対応中・完了の件数、高優先度の未完了案件、エラー・要確認の案件、作業時間の削減効果 |
| 処理ログ | いつ・どの案件で・何が起きたか（APIキーなどの秘密情報は記録しない） |
| 設定 | 会社名、分類ルール、優先度の基準、返信トーン、署名、AIモデル、手作業の想定時間 |

## 状態の意味

**AI処理状況**

| 状態 | 意味 | 担当者がすること |
|---|---|---|
| 受付済 | 原文を保存した直後 | なし（自動で処理中に進む） |
| 処理中 | AI分析・タスク・下書きを作成中 | なし（10分以上このままなら再処理の対象） |
| 完了 | すべて成功 | 下書きを確認・修正して送信 |
| 要確認 | 人の判断が必要（命令文の混入、原文に無い金額、下書き作成結果が不明 など） | 「注意・エラー内容」を読んで確認 → 「選択中の行の案件を再処理」 |
| エラー | 失敗したが安全にやり直せる（API通信失敗など） | メニュー「エラー・未完了の案件をまとめて再処理」 |

**対応状況**（担当者が変更）：未対応 → 対応中 → 完了

## セキュリティ対策（実装済み）

- OpenAI APIキーは **スクリプトプロパティ** に保存し、ソースコード・シート・ログには一切書かない
- 権限は `appsscript.json` で必要最小限に限定（Gmail は「下書き作成」用の `gmail.compose` のみで、受信メールの閲覧権限は持たない。スプレッドシートは「このファイルのみ」）
- メール送信処理はコード上に存在しない（ローカルテストで自動確認）
- 問い合わせ本文中の命令文（プロンプトインジェクション）に従わないよう指示し、検知したら「要確認」
- AIが原文に無い期限・金額・日付を書いた場合は採用しない／「要確認」にする
- 「=」で始まる入力が数式として実行されないよう、文字列として保存（数式インジェクション対策）
- 改行を含む不正なメールアドレスでは下書きを作らない（メールヘッダーインジェクション対策）

実際の企業で使う場合に追加すべき対策は、`docs/03_システム説明書.md` の6章にまとめています。
