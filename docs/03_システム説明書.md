# FlowPilot システム説明書

## 1. どんなシステムか

FlowPilot は、小規模な会社に届く問い合わせへの「最初の対応」を、AIで下準備するシステムです。

| これまで人がしていた作業 | FlowPilot がすること |
|---|---|
| 問い合わせを読んで、種類を見分ける | AIが4種類（見積依頼・日程調整・サービス相談・その他）に分類する |
| 内容を台帳に書き写す | 原文・要約・必要な対応・不足情報をスプレッドシートに記録する |
| 急ぎかどうかを判断する | 優先度（高・通常・要確認）を付け、緊急の案件をダッシュボードの上に表示する |
| やることをメモする | Google Tasks に「【分類】〇〇様への△△」というタスクを作る（期限が書かれていれば期限も設定） |
| 返信メールを一から書く | Gmail に返信の **下書き** を作る（**送信はしない**） |

最後に内容を確かめ、修正して送信するのは、必ず人です。AIは下準備だけを担当します。

**対象の利用者**：問い合わせ窓口を専任で置けない、従業員数人〜数十人の会社（デモでは、架空の設備工事会社「株式会社みなと設備工業（架空）」を想定しています）。

## 2. 全体の構成

```
[お客様] ──送信──▶ Googleフォーム
                        │ 送信されたら起動（トリガー）
                        ▼
                  Google Apps Script（FlowPilot本体）
                   │        │          │           │
          ① 原文を保存   ② AI分析    ③ タスク作成   ④ 下書き作成
                   ▼        ▼          ▼           ▼
            スプレッドシート  OpenAI API  Google Tasks  Gmail（下書きのみ）
            （案件管理・ダッシュボード・処理ログ・設定）

          ＋ 10分ごとの自動復旧：止まった案件・記録漏れを自動で処理し直す
```

| 使うサービス | 役割 | 料金 |
|---|---|---|
| Google フォーム | 問い合わせの受付窓口 | 無料 |
| Google スプレッドシート | 案件の台帳、ダッシュボード、設定 | 無料 |
| Google Apps Script | 全体を動かすプログラム | 無料（1日の実行時間などに上限あり） |
| OpenAI API（Responses API） | 分類・要約・返信文案の作成 | 使った分だけ（`gpt-6.1-terra` の場合、1件あたり1円前後の見込み（入力約2,000・出力約800トークンで計算した概算）） |
| Google Tasks | 対応タスクの管理 | 無料 |
| Gmail | 返信の下書きの保存 | 無料 |

## 3. 処理の流れと、失敗への備え

1. **受付**：受付ID（例：`FP-20261112-0001`）を発行し、何よりも先に原文を保存します。このあと AI が失敗しても、問い合わせは消えません。
2. **AI分析**：分類・要約・優先度・期限などを、決められた形式（JSON Schema）で受け取ります。
3. **プログラムでの検証**：AIの答えを、そのまま信用しないようにしています。
   - 決められた分類以外の答えは「その他」にして、「要確認」にする
   - 期限は、フォームに入力された日付を優先する。AIが本文から読み取った日付は、本文にその日付が実際に書かれている場合だけ採用する
   - 本文にない金額や日付が返信文に書かれていたら、「要確認」にする
   - 命令文が混ざっていそうなら、「要確認」にする
4. **タスク作成 → 下書き作成**：作る前に「作成中」の印を付けて、途中で止まっても二重に作られないようにしています。
5. **結果**：「完了」「要確認」「エラー」のどれかになります。

| 起きうる失敗 | 備え |
|---|---|
| OpenAI が混雑している、一時的に応答しない | 自動で数回やり直す。だめなら「エラー」にして、あとで再処理する |
| 同時にたくさん届いて処理が重なる | 順番待ち（ロック）で1件ずつ処理する。間に合わなかった分は自動復旧で拾う |
| 処理の途中で止まった | 10分以上「処理中」のままの案件は、自動復旧で処理し直す |
| 記録自体に失敗した | 自動復旧が、過去3日分のフォームの回答と台帳を照らし合わせて取り込む |
| 何度やっても失敗する | 自動の再試行は3回まで（料金のむだ遣いを防ぐ）。以降はメニューから手動で再処理する |

## 4. 業種を変えるとき（販売用の土台として）

プログラムは変えずに、「設定」シートの書き換えだけで、ほかの業種に合わせられます。

| 設定項目 | 例（設備工事会社） | 例（税理士事務所に変える場合） |
|---|---|---|
| 会社名・事業内容 | 給排水・空調・電気設備の工事 | 中小企業向けの税務・会計 |
| 問い合わせ分類 | 見積依頼／日程調整／サービス相談／その他 | 顧問契約の相談／面談予約／書類の質問／その他 |
| 高優先度の基準 | 水漏れ・漏電・ガス臭など | 申告期限が近いもの、税務調査の連絡など |
| 返信のトーン・署名・AIモデル | 自由に変更できる | 同左 |

※分類を変えたら、その業種向けのテストデータで正解率を確かめ直してください。

## 5. セキュリティ対策（実装済み）

| 心配なこと | 対策 |
|---|---|
| APIキーが漏れる | スクリプトプロパティに保存し、ソースコード・シート・ログには書かない。`.gitignore` で認証ファイルも GitHub に上がらないようにしている |
| 必要以上の権限を持つ | Gmail は「下書きを作る」権限だけで、受信メールは読めない。スプレッドシートは「このファイルだけ」にアクセスする |
| 誤ってメールが送られる | 送信する処理がプログラムの中に存在しない（PC上の模擬テストで毎回確認） |
| 問い合わせに AI への命令が書かれている（プロンプトインジェクション） | 問い合わせ文はデータとしてだけ扱うよう AI に指示している。命令文が見つかったら「要確認」にする |
| AI が事実でないことを書く（ハルシネーション） | 本文にない期限は採用しない。本文にない金額・日付は「要確認」にする |
| `=` で始まる入力が数式として実行される | 先頭に `'` を付けて、文字として保存する |
| メールの宛先欄に細工をされる | 改行を含むなど不正なメールアドレスでは、下書きを作らない |
| とても長い文章で料金がかさむ | AI に渡す本文を4,000文字までに制限している |

## 6. 実際の企業で使う前に追加すべき対策

このシステムは課題用のデモで、架空のデータでしか動かしていません。実在する会社の、実在するお客様の情報を扱う場合は、少なくとも次の対策が必要です。

### 個人情報・契約
- **プライバシーポリシーへの明記**：お客様の問い合わせ内容を AI（外部の事業者）に送ることを、フォームとプライバシーポリシーに書き、同意を得る。
- **OpenAI のデータの扱いを確認**：API に送ったデータの保存期間や、学習に使われるかどうかを、契約時点の規約で確認する。必要に応じて、データを保存しない設定などを申し込む。
- **AI に送る情報を減らす**：電話番号・住所などは AI に送らずに処理する仕組み（マスキング）を検討する。
- **保存期間を決める**：台帳・ログ・下書きを何年保存し、いつ削除するかを決める。

### アカウント・権限
- **会社専用のアカウントで動かす**：個人の Google アカウントではなく、Google Workspace の業務用アカウントで動かし、担当者が辞めても止まらないようにする。
- **共有範囲を絞る**：スプレッドシートとフォームの共有を、必要な社員だけにする。2段階認証を必須にする。
- **APIキーの管理**：会社ごとに別のキーを使い、利用上限額を設定する。定期的に作り直し、担当者が辞めたら無効にする。

### 運用・監視
- **エラーに気づける仕組み**：「エラー」「要確認」が出たら、担当者にメールで知らせる。
- **料金の上限**：OpenAI の管理画面で月の上限額と通知を設定する。
- **送信前のチェックを決めておく**：送信前に、宛先・金額・日付・約束した内容を確かめるルールを作る。
- **迷惑な大量送信への対策**：フォームに reCAPTCHA などを付ける。1日の処理件数に上限を設ける。

### 品質
- **実際の問い合わせで再評価**：本番で使う前に、過去の実際の問い合わせ（個人情報を消したもの）で、正解率を測り直す。
- **定期的な抜き取り確認**：月に1回、AI の分類と人の判断がずれていないかを確かめる。

## 7. 今回やらないこと（対象外）

Web のダッシュボード、メールの自動送信、受信メールの監視、LINE・Slack との連携、複数の会社を1つで管理すること、ログイン機能、音声、PDF、料金の自動計算、Google カレンダーとの連携。

## 8. わかっている制限

- Apps Script の制限で、1回の処理は6分まで、1日の実行時間にも上限があります。月に数千件のような大量の問い合わせには向きません。
- AI の判断は100%正しいわけではありません。必ず人が確認してから送信してください。
- 期限は「12月10日まで」のように日付が書いてあるときだけ設定します。「来週の金曜日」のような書き方は、間違いを防ぐため、あえて読み取りません。
